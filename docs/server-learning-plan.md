# 家庭档案、正式考核与成长积分

当前实现保留静态教学版本，并增加可选的 Node 服务。普通静态目录和单文件课堂保存本机练习；通过 Node 的 `/mathphysics/` 使用账号、多个学习档案、存档同步和正式考核。原课堂完成记录、小游戏本机分数、旧浏览器记录和教师题目预览均不增加正式成长积分。

服务采用 Node 24.14.0 内置 `node:sqlite`，已固定运行时为 SQLite 3.51.2。数据库使用 STRICT 表、外键、WAL 和 FULL 同步。SQLite、WAL、SHM、运行锁和备份须位于静态根目录外，路径检查会解析已有目录及 junction。无需新增 SQLite npm 依赖。启动、账户初始化及本地运行命令见 [运行说明](server-learning-operation.md)。

## 存档归属与同步

每个档案属于一个账号。服务器从 HttpOnly 会话确定账号，验证请求中的档案归属；客户端不能通过提交 accountId、profileId 或昵称绕过归属检查。密码经 scrypt 处理，浏览器缓存不保存密码。修改请求需要同源 Origin 和当前 CSRF token。

客户端按账号 ID 与档案 ID 缓存练习、已签发考核和待同步队列。切档先采集当前练习，随后增加 epoch、取消在途请求、解绑旧 provider 和存储句柄。首页关闭旧课堂 iframe；脱离页面或旧 epoch 的异步回调不能写入新档案。登录过期时清除账号和档案界面，原账号缓存及服务器记录仍按原归属保留。

练习存档携带 `expectedRevision` 和 `mutationId`。同一 mutation 重放返回原结果；相同键配不同内容返回 409。修订号过旧返回 409 及当前服务器副本，客户端保留两份，等待明确选择。恢复历史修订创建新修订，不覆盖历史。断网后继续写同档案本机副本，联网后只重放该档案队列。

旧记录导入需要先预览、确认归属，再作为 `legacy/unverified` 备份入库。导入和恢复均为 0 分，保留原浏览器键及恢复副本；旧题目答案、完成数和客户端积分不能变成正式结果。

## 服务端考核

客户端只选择已公布的目标及难度。服务器决定种子、固定题量、年级分组、满分、兼容版本、计分规则和积分桶，冻结私有题目定义及逐题快照；公开 DTO 不含 grading、solution 或种子。所有正式考核通过 `/learning/` 作答，课堂中的自由操作仍是练习。

交卷仅接受 `{responses, idempotencyKey}`。responses 以公开题目 ID 对应原始数值文本、选项索引或允许的操作结构；客户端 score、correct、题量、规则版本及归属字段被拒绝。多量名应用题使用公开 `publicInput.parts` 渲染分项输入，内部打包各项原始字符串；服务器严格检查字段和 typed 答案，不执行算式字符串。全部1391道无隔离应用题按原分类可练习，仅7道既有问题题保留隔离。取消1123/268固定分区和家族数门槛；来源、故事和题族仅供溯源。1390道映射到40个既有数学目标，1道具体目标待决项单列，仍可练习；不增加目标、奖励桶或隔离。原267条逐题数学关系依据保留，新增映射复用既有分类/数学关系规则，不宣称对1391题进行了新的逐题目标教学审读。所选分类题量不足时由同一目标、同一难度的原生签发器补足原固定题量。同目标与难度继续共用历史最佳增量及原100分上限。人工批准字段如实保持false，真实助手复核记录保留；正式题仍由服务端签发并判原始回答，固定服务端内容指纹保证发布一致性。

同一交卷键及相同内容只判定一次；另一设备已先交卷时，迟到副本返回 `attempt_finalized`。界面使用服务器正式原始答案显示结果，同时保留本机未提交副本。已签发题可离线作答并冻结交卷；联网确认前不展示正式结果或增加积分。

## 成绩、积分与归因

原始成绩按整数四舍五入标准化为 0 至 10000 最小单位，100 单位显示 1.00 点。同一目标、年级分组、难度、兼容规则及积分版本构成固定桶。仅历史最好成绩的正向差额增加积分，每桶最多 10000 单位；重复同分、重复提交和换来源池重抽同家族题均不会重复奖励。

服务器按已判定逐题得分，用最大余数法与稳定题序分配整数增量。每笔流水保留考核、题目 ID/版本、逐题键、规则版本、归因修订及触发修订。总积分等于流水之和，模块贡献之和也等于总积分。正式交卷、逐题成绩、积分流水和完成存档在同一事务中保存。练习存档不能写入服务器拥有的 `assessment:*` 命名空间。

成长页分别显示未测、已测零分、首次、最近和历史最好，并按兼容桶比较。同一桶结构或满分变化会被拒绝，规则改变应创建新兼容桶。积分反映已观察到的考核最好成绩增量，不表示精确掌握度，也不能证明独立作答。

## 数据核验与恢复

`verify` 检查 SQLite 完整性、外键、冻结定义、题目快照、各次成绩修订、原始总分与标准化分数、积分归因、最佳汇总及完成修订。`backup` 使用 SQLite 备份接口并验证生成文件；`restore` 先验证合成/授权备份，再恢复至静态根外。恢复、重建和重判要求服务停机，运行锁阻止误用。

原始交卷和成绩修订不可改写。重判只通过本地 CLI 追加修订，记录原因和安装中的 grader 版本，并生成可追溯的积分补差或冲销；客户端没有写积分流水或发起重判的 API。

接口字段见 [API 合约](api-contract.json)，当前目标及 0 分边界见 [考核覆盖](assessment-coverage.md)，各课堂可恢复范围见 [同步适配](sync-adapters.md)。本地验收报告位于交付源码外的 evidence；报告结果对应实际运行的版本，不沿用历史候选的通过数量。
