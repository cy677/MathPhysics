# 维护与逐步开放

## 第一版的三个独立层

1. 上游资源层 vendor：保存原始程序、完整题目生成器、示例、源码与许可证，不按年级删减。
2. 清单适配层 config/inventory.json、src/adapters：声明原版入口、类型、年级建议、来源和证据。不混淆固定关卡、随机出题、自由实验、开发示例。
3. 宿主教学层 src/app.js、state.js：主题入口、筛选、预览、开放配置、访问记录。将来再加任务和奖励，不侵入当前上游。

## 新增或开放内容

已有活动只修改 defaults.json 或工作台配置。新增资源应先核查许可、固定版本、保留完整内容、加入导入器与清单，再补充适配器和浏览器测试。不要手动编辑生成的 inventory.json。

前端过滤只影响展示；默认关闭不能成为缺少实际资源的借口。构建测试须逐项验证所有 entry 和原版 Matter 索引，并核对全部文件哈希。

## 模块级与题目级边界

第一版进入 PhET 后原版全部内部导航可用。首页逐项开放不等于逐题锁定，普通 PhET 也不提供本项目所需的统一通关 API。本版不使用需要额外许可的 PhET-iO。未来题目级改造先核对开源构建和许可证，明确每个活动的 start / ready / progress / complete / dispose 事件，再接入教学任务。

## 数据

localStorage 键为 mathphysics.state.v1。openIds 管理宿主开放内容，visited 记录成功启动时间，teacherPreview 是展示开关。没有姓名、年龄、账号和服务器记录。配置导入只修改 openIds，不覆盖 visited。更新版本应做明确迁移，不通过全量清空浏览器数据修复问题。

## 上游更新

原始压缩包、下载URL、Git提交SHA、SHA256锁与每个落地文件的哈希都必须保留。现有文件哈希不符时导入器拒绝覆盖。升级需要独立分支，审查上游许可证和新增/删除条目后显式更新锁，不要在日常启动时访问 latest。

源码与成品是两条来源链。PhET使用官方分发HTML，而源码快照未包含完整公共依赖构建环境，不能宣称源码快照必然能复现同一成品。后续修改源码需要另行建立完整依赖锁和构建流程。

## 测试

Node测试：完整索引、有效入口、SHA256、默认子集、全年级标签、状态容错、配置白名单、无授权项目排除。
浏览器测试：关闭外网访问的Chromium，逐个启动所有活动、检查canvas/本地404/未捕获异常；宿主开放持久化、恢复默认、返回销毁实例；平板视口导航。不是任意随机题目的完整求解，也不代替Safari实机触摸测试。
